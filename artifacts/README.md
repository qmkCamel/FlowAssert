# 产物存放与提交规则

| 目录 | 用途 | Git 提交 |
| --- | --- | --- |
| `artifacts/local/` | 测试和探针输出、临时截图、原始真机材料、录像、日志、本机诊断 | 忽略，不提交 |
| `artifacts/curated/` | 人工挑选并审查的文档插图、脱敏 Mock 截图、精简验收摘要 | 按需提交 |

默认写入 `local/`；不确定是否适合公开时，也留在这里。不要用 `git add -f` 绕过忽略规则。`curated/` 表示允许进入提交审查，并不代表其中任意新增文件已经获得隐私或验收批准。产物根目录只保留本说明和这两个子目录。

## 从运行结果到提交材料

1. 测试、探针和手工取证都将新结果保存到 `local/<主题>/`，失败时保留原始证据；自动任务不得覆盖 `curated/`。
2. 检查截图和数据，移除账号、通知、设备标识、凭据、主机路径与私人业务内容；优先用 Mock 或合成示例。原始真机截图、录像、日志和设备配置继续留本机。
3. 只复制确有文档或审查用途的最少文件到 `curated/<主题>/`。附上用途、来源、验证日期和边界；长日志应提炼为 Markdown 摘要。
4. 更新文档引用；新增或修改媒体时，检查内容并更新仓库根目录的 `public-media-review.json` 路径、SHA-256 和审查说明。不要仅为通过检查而刷新哈希。
5. 运行 `pnpm artifacts:check` 和 `pnpm public:check`；提交前遵循项目完整门禁。目录检查不替代人工内容检查。

Viewer 的“保留并检查运行截图”可以在 `local/` 完成；仅在需要随代码留档时才选入 `curated/`。CI 上传的运行证据仍从 `local/` 收集，遵循原有保留期限。两个目录都不加入安装包。
