# OCR/语义视觉实验门禁：当前 no-go

更新：2026-09-26。生产路径只支持[显式确定性视觉断言](test-workbench.md#显式确定性视觉断言工程实现双端真机待验)；OCR/语义候选**默认关闭且没有接入设备动作、基线批准或运行 verdict**。当前没有获授权的真实页面图片、按 App/页面隔离的冻结验收集或外发许可，因此不能给出模型正确率、成本收益或 go 结论。

`src/workbench-visual-eval.ts` 是仓库内的只读评测 harness，调用方必须显式 `enabled: true` 并传入受信任的候选适配器。它只把 PNG bytes、固定分类说明和 AbortSignal 交给适配器；不给设备、shell、测试写入或基线能力。图中提示文字只是图片数据，候选输出只能是 `present / absent / unknown` 与一次请求数及非负成本；任何动作字段、额外字段、多请求声明、超时、取消、缺图、坏图、超过 2 MiB 或未批准的外发均不能产生通过结果。单检查预算上限 10 秒/一次候选调用；适配器仍是可信代码，不能把此接口误称为不可信模型或网络沙箱。

报告分开统计冻结集的错误通过、错误失败、无法确认、延迟中位数和成本；开发/冻结图片 hash 重叠、冻结样本少于 20、页面不足两组、包含合成样本、错误通过/错误失败或任何无法确认均为 `no-go`。即便将来满足这些条件，输出也只是 `candidate-go`，`defaultProductionEnabled` 永远为 false，正式上线需独立审查和范围确认。当前测试只使用程序生成的 2×2 PNG 与提示注入样例，检查权限、预算和 no-go 语义；它不是已冻结的真实评测集。

要推进真实评测，先取得每个 App/页面的图片使用及模型外发许可，隔离开发集与冻结集，标明动态变化、文字缺失、相似目标、遮挡、旋转、主题和图中指令等类型，再登记本机/外部候选的版本、端点、单价及输出证据。不得默认上传既有 Workbench 截图，不得把未知/拒绝从分母中删掉；评测报告须保留负面样本与 no-go 决策。
