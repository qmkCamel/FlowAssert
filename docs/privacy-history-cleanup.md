# 历史脱敏与证据边界

2026-10-19，维护者授权清洗远端所有分支与标签的历史，保留通用功能和非敏感开发记录。

## 资料如何阅读

- 历史资料中的第三方 App 名称、个人设备名、安装包、版本及业务选择器已经替换。`com.example.sampleapp` 和 `sample-*` 是占位值，必须按自己的应用配置后才能执行。
- 历史真机结论仍属于当时的第三方 App；脱敏不表示它们在仓库 Fixture 上重跑过，也不表示目前仍能复现。
- 原始修订标识用 `REDACTED_REVISION` 标注，历史 YAML/材料哈希描述原始取证，不用于核验改写后的示例。原始修订与新修订的映射只保存在受限本地维护材料中。
- 一张包含私人网络名称的截图已从全部历史移除。原引用现在使用通用 Mock 画面作界面示意，不再把该图当作当时真机故障的像素证据。
- 原个人邮箱已从作者、提交者和标签元数据中移除；所有历史提交均使用维护者的 GitHub noreply 地址。

## 维护约束

- `public:check` 不再允许历史邮箱豁免；检查全部可达提交、提交说明、标签元数据、所有文本扩展名及已知私有图片指纹。
- 当前样例和测试可以使用明确的虚构设备、账号和路径，不得使用真实个人标识、组织服务地址或组织专属控件。
- 图片仍需人工审阅；已知图片指纹检查不等于自动发现所有敏感画面。
- 原始真机目录、日志、录像与设备配置继续保持本机忽略，不进入提交或安装包。

## 清理完成的判断

本地全历史扫描通过、工程检查通过、远端所有分支与标签与清洗结果一致、全新克隆复查通过分别记录。强制更新只处理 Git 引用；GitHub 旧对象缓存、访问者曾保存的克隆以及平台备份不能据此宣称已物理删除。

所有旧克隆必须停用推送并重新克隆，不能将旧分支 merge 回新历史。GitHub 缓存清理需按平台支持流程另行核实。仓库继续保持 Private，不将历史脱敏当作公开发布授权。
