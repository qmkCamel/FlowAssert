# Workbench reliability matrix

This matrix is the deterministic software acceptance boundary for `harden-workbench-adoption`. It records the expected verdict, whether another device action may be dispatched, and the retained evidence. Physical-device rows remain separate OpenSpec tasks and are not implied by these Mock/fake-driver checks.

| Fault / phase | Expected result | Further action dispatch | Evidence / ownership invariant | Automated coverage |
| --- | --- | --- | --- | --- |
| Device action transport fails after mutation | `inconclusive`; device control fenced until reconnect | No | Dispatch remains uncertain; run lease is released only after in-flight control settles | `workbench.test.ts`: uncertain dispatched action; cancellation drains controls |
| Device source/XML fails while PNG succeeds | `inconclusive` | No next flow action | PNG remains registered; checkpoint identifies XML failure | `workbench.test.ts`: source-only checkpoint failure |
| Device PNG fails while XML succeeds | `inconclusive` | No next flow action | XML remains registered; checkpoint identifies PNG failure | `workbench.test.ts`: image-only checkpoint failure |
| Locked/unexpected screen fails a declared assertion | `fail` when the readable evidence deterministically disproves the assertion | No mutation for an assertion-only flow | Screenshot/XML retained; no inferred unlock or dismissal action | assertion/blocker and negative-flow tests |
| Rotation / viewport change | Continue only after fresh geometry and observation binding; otherwise reject stale coordinates | Only a newly validated action | Geometry is read at the action boundary; checkpoint capture does not silently remap coordinates | `workbench.test.ts` geometry budget; Appium orientation tests; capture rotation E2E |
| Manifest write fails after evidence commit | `inconclusive` in memory and after restart | No replay | Immutable committed files recovered as unverified; original manifest backed up | `workbench.test.ts`: manifest failure and restart recovery |
| Structurally corrupt manifest | synthetic `inconclusive` metadata entry | None | Corrupt bytes retained and backed up before any repair | `workbench.test.ts`: corrupt-manifest recovery |
| Cancel during prepare extension | `cancelled` or interrupted/unknown after host death | No UI execution | Registered cleanup tokens are retained privately and never replayed blindly | extension cancellation and killed-preparation orchestration tests |
| Cancel during execution | `cancelled` after in-flight action convergence | No later flow action | Last usable preview/evidence remains available | Workbench and suite cancellation tests |
| Failure during evidence capture | `inconclusive` | No later flow action | Successful side of PNG/XML pair remains immutable and visible | single-side checkpoint tests |
| Cleanup extension fails | non-clean result; suite/job infrastructure exit takes precedence | No subsequent case when state is uncertain | Original test outcome and cleanup error are both retained | orchestration cleanup-failure tests; managed-job cleanup precedence |
| SIGINT/SIGTERM managed job | job `130` only after bounded owned-resource cleanup | No new dispatch | Accepted suite is cancelled/drained once and never replayed | managed-job child-process SIGINT test |
| Total job timeout or shutdown uncertainty | job `2` | No new dispatch | Suite result remains separate; all errors retained | managed-job timeout/shutdown tests |
