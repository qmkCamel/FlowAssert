## 正文（可复制）

### 修好了，然后呢？把手机上的一次验证，留下来。

一个移动端问题修完了。你拿起手机，打开 App，找到入口，点了几下，看到了预期结果。

几天后，同事问：“上次是在什么页面测的？失败时长什么样？这次改完再跑，旧问题还会出现吗？”

一句“我测过了”，往往回答不了这些问题。截图可能在聊天里，操作步骤靠记忆，下一次回归又得重新走一遍。

我做了一个本机移动测试工作台 **FlowAssert**，希望把这次验证留下来。

连接 Android 或 iPhone 后，你可以在电脑上看设备画面，通过 Inspector 查看页面节点，把重复操作保存成可读的 YAML 用例。运行时看得到进度，每一步的截图、界面结构和断言结果都跟着运行记录保存。

如果第四步失败，就回到第四步：用例期待什么，当时页面是什么，后面的步骤有没有执行。修改用例后再跑，会产生新的记录；旧失败仍然保留。重新打开工作台，也能从用例历史里找到这两次运行。

需要让同事查看时，可以从报告选择材料、遮蔽图片中的敏感区域，审查最终预览，再下载离线 HTML。接收者不需要连接你的手机或打开你的本机服务，就能阅读这份结果。报告会明确标注它是派生材料，没有重新执行测试；完整私有日志、YAML 等也不会自动装进这份阅读文件。

固定流程无需每步调用模型。独立工作台不要求 DeepSeek Harness 或模型凭据，环境预检也只检查你本次操作需要的依赖。想用 Agent 时，再通过 MCP 或 DSH 接入同一套设备核心。

FlowAssert 目前仍是 **Developer Preview**。基础执行、步骤取证、历史回看和录像等能力已有 Android/iPhone 真机样本；更广设备覆盖、外部真实业务、独立用户体验仍在验收中。页面显示成功不等于后端业务通过：需要独立业务验证时，项目必须配置自己的只读真值检查。未配置的项目不会自动被标成业务通过。

代码扩展和有限 AI 导航恢复已有实现与限定样本证据；更进一步的证据驱动修复仍默认关闭，尚不能宣传成自动完成真实 App 修复。首次体验不需要启用这些能力。

这次先邀请 **3–5 位开发者或测试维护者**来试一个小闭环：跑通 Mock、制造一次失败、找到证据、改完再跑、下载报告。再带一个自己经常手动验证的真机场景，看看哪些操作值得留下来。

源码采用 MIT；本轮直接克隆 dev 分支体验，反馈时带上提交 SHA，不需要领取独立内测包。如果你卡住了，也请留下卡住的步骤和耗时——这正是这轮内测要找的问题。

## 短版（邀请文案）

做了一个本机移动测试工作台 FlowAssert：在电脑上看 Android/iPhone，把重复操作保存为 YAML，失败时回到具体步骤查看截图和断言，改完再跑也保留旧失败。结果可以审查后导出离线 HTML 给同事阅读。

目前是 Developer Preview，想先找 3–5 位开发者或测试维护者内测。首轮用 Mock，不需要手机、模型凭据或 DSH；之后再选做自己的真机场景。最希望知道的是：第一次在哪一步卡住，能否看懂失败，以及下次是否愿意复用这个用例。

[内测任务卡](../beta-start.md) · [交互演示](mobile-mirror-demo.html)。真机需要对应 Appium/平台环境，iPhone 另需 Xcode/WDA 签名；AI 修复仍默认关闭。

## 90 秒演示脚本

| 时间 | 画面 | 口播 |
| --- | --- | --- |
| 0–10 秒 | 演示页标识与首屏 | “修好一个问题以后，怎么把这次验证留下来？这里用离线 Mock 说明，整个过程不连接手机。” |
| 10–25 秒 | 成功流程、步骤画面和断言 | “把固定操作存成用例，每一步的结果都有对应画面。真实工作台还保存界面结构和材料校验。” |
| 25–40 秒 | 切换失败流程，查看第 4 步 | “这次期待两次点击，实际只有一次。第五步不会继续，失败保留。” |
| 40–55 秒 | 修正期望，新运行复验 | “这个示例的问题在用例期望。确认后改成一次，再生成一条新记录，不把原来的失败改成通过。” |
| 55–75 秒 | 对比两条模拟记录，预览并下载 | “同事可以拿到一份可读报告。本页下载的是模拟样例；真实产品要求先审查材料和遮蔽范围。” |
| 75–90 秒 | 内测任务卡与范围 | “先从不需要手机的 Mock 开始，再选自己的真机场景。告诉我们卡在哪里，帮助下一位用户更快完成第一次验证。” |

演示录像与本轮验证见[演示验证记录](beta-demo-validation.md)。录像是交互宣传页的实际操作录屏，不是手机录像或产品执行耗时证明。

## 素材与证据边界

- 演示默认单文件 Mock，修正的是故意设置错误的期望值；真实失败需要先核查原因，不能机械地把期望改成实际。
- “新运行”“历史”“报告下载”在宣传页内使用预设模拟数据，刷新即清空；真实产品持久化能力以[工作台指南](../test-workbench.md)和[报告指南](../report-reading-and-sharing.md)为准。
- 当前[工作台主图](../../artifacts/screenshots/mobile-mirror-workbench-evidence.png)等 20 张图片已于 10 月 8 日刷新，来源见[截图记录](../screenshot-refresh-2026-10-08.md)。均为 Mock/合成材料，不当作新真机证据。
- 历史 Android 第三方 App原始回放仍可在本机显式加载。`local-case-assets/` 不随源码分发，原图未脱敏，不作为内测共享素材。原件导出方式仍为 `python3 scripts/export-promo-case.py`；历史素材与 9 月验证见 Git 历史，不改写原证据日期。
- 内测使用 dev 分支，记录本次提交 SHA，不声称 alpha.2 已公开发布。DSH 当前验证基线为 `0.2.0-rc.2`；实际模型图片、独立体验、广泛设备与真实业务验收分别跟踪。
