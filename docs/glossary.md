# FlowAssert 名词解释

面向首次阅读项目文档的研发和测试同学。本页说明术语在 FlowAssert 中的含义；具体支持范围与操作步骤以[文档目录](https://github.com/qmkCamel/flowassert/blob/main/docs/README.md)中的指南为准。

Inspector、Viewer、Provider 等是开发工具中的常见称呼，这里用于命名本项目的功能或组件；`MirrorService` 是项目中的具体类名。MCP 是接入协议，DeepSeek Harness 是外部宿主产品。遇到这些词时，先看它在本项目里承担什么职责。

## 界面与设备组件

<a id="inspector"></a>

### 界面检查器（Inspector）

项目内置的界面检查功能：获取某一时刻的截图和节点树，选择节点后查看文字、标识、类型、位置与状态。冻结的是检查视图，手机仍可继续变化；点击检查目标不会直接点击手机上的控件。

例如：选中“提交”按钮，查看它的标识与可点击状态，辅助生成定位器或断言。用法见[工作台指南](test-workbench.md#inspector-辅助创作fixture样本已验真实构建变更待补)。

<a id="viewer"></a>

### 本机工作台界面（Viewer）

在浏览器中打开的本机界面，提供设备画面、连接助手、Inspector、用例编辑、运行历史和报告阅读。Inspector 是其中的一项功能。

例如：打开启动器打印的本机地址，在“设备”连接手机，再到“运行记录”查看失败截图。

<a id="provider"></a>

### 设备控制适配层（Provider）

项目中将统一的设备接口适配到具体控制方式的组件。MockProvider 操作模拟设备；AppiumProvider 通过 Appium 操作真实 Android 或 iPhone。

例如：同一个“截图”请求由所选 Provider 获取画面。这里的 Provider 指设备适配层；其他上下文中的“模型 provider”指模型服务提供方。

<a id="mirror-service"></a>

### 设备控制服务（MirrorService）

项目中的核心服务，管理设备会话、操作队列、状态和观察结果。Viewer、MCP 和 DSH 通过共享核心使用设备能力。

例如：工作台运行占用设备时，由共享核心约束其他手动操作，避免互相干扰。组件关系见[架构文档](architecture.md)。

## 测试与证据

<a id="observation"></a>

### 界面观察快照（Observation）

一次采集得到的界面信息，带有身份、时间和有效性信息，可包含截图、节点结构与几何信息。截图和结构可能是先后获取的，不保证是设备上的原子快照；基于它执行动作时还需检查新鲜度和会话状态。

例如：Agent 获取页面后选择一个按钮；页面变化或观察过期后，需要重新获取，不能继续沿用旧节点。

<a id="locator"></a>

### 控件定位器（Locator）

用来找到目标控件的条件，例如标识、文字或控件类型。Inspector 可以辅助构造候选，是否唯一匹配、是否跨版本稳定仍需核对。

例如：用按钮的稳定标识定位“提交”，再执行点击或可见断言。

<a id="fixture"></a>

### 受控测试场景（Fixture）

为可重复验证而准备的测试 App、数据或环境。文中的 Fixture App 指仓库内的测试应用，使用合成数据；它可以在真实手机上运行。

例如：用合成订单验证金额是否写入独立数据库。它证明该场景的执行结果，不代表线上订单系统已经验收。

<a id="baseline"></a>

### 比较基线（Baseline）

比较时明确选择、并符合相应规则的参考对象。运行比较的基线是另一条运行记录；视觉检查的基线是批准的参考图。最近一次成功或同名用例不自动等于可比基线。

例如：比较同一用例、相同输入和平台的两次运行；环境或材料缺失时，需要显示比较限制。

<a id="verdict"></a>

### 运行判定（Verdict）

按照声明的检查条件、清理和必需证据得出的运行结果。`pass` 只确认该运行要求的条件满足；未配置的业务或视觉检查会显示未执行。

例如：只检查“提交成功”文字的用例通过，不能据此认定订单金额已经正确保存。Agent 对失败的解释也不会改写原判定。

<a id="business-verifier"></a>

### 独立业务验证（Business verifier）

通过明确登记的验证逻辑，独立读取业务实际结果，并与期望比较。它与界面断言分别记录，不能由一张成功页面截图代替。

例如：页面显示提交成功后，读取服务端或数据库中的订单金额，核对实际值是否为 1200 分。

<a id="diagnostic-context"></a>

### 诊断上下文（Diagnostic Context）

项目为上层 Agent 提供的精简、可回钻的比较结果，包含运行身份、差异、证据引用和限制。Agent 可以据此解释原因，其解释不会改写原运行的事实和判定。

例如：先告诉 Agent 最早观察到差异的步骤，再通过证据引用查看该步骤的断言和截图。详见[比较指南](run-comparison-analysis.md)。

## 状态与接入

<a id="mock"></a>

### 模拟设备（Mock）

项目提供的确定性模拟设备，用于体验流程、开发和自动化测试，无需连接手机。Fixture 是受控场景，Mock 是模拟执行方式，两者含义不同。

例如：在 Mock 中走完成功、故意失败、复验和分享流程，证明软件流程可用；真机能力需要单独验证。

<a id="preview"></a>

### 预览状态（Preview）

表示项目或功能处于预览阶段，支持范围和验收仍有限。Developer Preview 描述项目交付状态；某项功能是否默认启用，应查看它自己的准入与配置。

例如：证据驱动修复属于默认关闭的 Preview 功能，试用前需要满足对应操作指南的条件。

<a id="physical-acceptance"></a>

### 真机验收（Physical-device acceptance）

在明确的真实设备、系统、构建和场景下执行验证，并保留结果与证据。结论只覆盖报告声明的范围。

例如：一台 Android 手机上的 Fixture 正反例通过，不代表所有 Android 机型或真实业务流程都已通过。

<a id="mcp"></a>

### 模型上下文协议（MCP）

Model Context Protocol 的缩写，是外部 Agent 宿主接入工具的协议。本项目的 MCP 适配器提供受授权的设备观察、控制和已登记测试能力。

例如：Codex 通过 MCP 获取一次设备观察或执行已登记测试；连续设备画面由本机 Viewer 展示。

<a id="dsh"></a>

### DeepSeek Harness（DSH）

外部 Agent 宿主产品，DSH 是本文档中的简称。FlowAssert 通过插件接入它，设备能力仍由共享核心管理。

例如：在已验证版本的 Harness 中加载插件，再按授权使用设备工具。支持版本与安装条件见[技术指南](technical-guide.zh-CN.md#工具链基线)。
