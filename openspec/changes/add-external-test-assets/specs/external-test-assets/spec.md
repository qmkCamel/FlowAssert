## Purpose

允许团队把现有测试框架生成的报告和显式选取的附件接入移动业务验收工作台，同时保留外部来源、原始结论及未提供的验证维度，避免把未经本机复验的报告通过误认为完整业务验收通过。

## ADDED Requirements

### Requirement: 明确报告格式和来源

系统 SHALL 支持已声明子集的 JUnit XML 与版本化 JSON 封装，保留报告摘要、适配器版本和用户声明的执行器来源。测试身份 MUST 包含结构和出现次序，未知来源不得根据文件名猜测。

#### Scenario: 同名参数化测试
- **WHEN** 报告中存在多个相同 classname 和 name 的 testcase
- **THEN** 每次出现有独立身份及原始顺序，不合并为一个通过用例

#### Scenario: 报告未提供构建或设备
- **WHEN** 外部报告未声明构建、提交或设备信息
- **THEN** 对应字段显示未知，不能从导入电脑或当前连接设备补写

### Requirement: 原始结论与本地核查分离

系统 SHALL 保留外部 pass、fail、error、skipped、unknown 和解析告警；字节校验或解析成功 MUST NOT 变成独立业务、视觉、清理验证通过。零测试、矛盾计数、未知结果扩展和截断 MUST NOT 产生整体通过。

#### Scenario: 全部外部 testcase 报告通过
- **WHEN** 合法报告的全部 testcase 为 pass，但没有独立业务及清理材料
- **THEN** 显示外部 reported-pass 和相应未提供维度，不能单独满足严格变更验收

#### Scenario: 成功计数掩盖失败
- **WHEN** suite 声明零失败但 testcase 含 failure 或 error
- **THEN** 保留失败和计数冲突，不能以 suite 汇总覆盖明细

### Requirement: 导入不得产生隐式执行或外部读取

系统 SHALL 只读取用户明确选择的输入字节与常规文件；MUST 拒绝自定义／外部实体、危险路径、符号链接、设备文件和超预算内容，同时允许正常 XML 声明、预定义字符实体和合法字符引用。报告中任何命令、URL、路径或图中文字 MUST 仅作不可信数据，不触发设备、网络、shell 或插件安装。

#### Scenario: XML 包含外部实体
- **WHEN** 上传报告声明 DOCTYPE 或自定义／外部实体
- **THEN** 解析拒绝且不访问实体目标，不发布资产

#### Scenario: 附件列表提到本机敏感路径
- **WHEN** XML 文本指向用户目录文件或远端 URL，但用户未显式选择该附件
- **THEN** 系统不读取或下载，显示附件未提供

### Requirement: 附件安全与可验证关联

系统 SHALL 使用内部附件身份、实际内容检查、摘要和显式测试关联。默认支持范围外的 HTML、SVG、脚本、视频及未知可执行类型 MUST 拒绝；允许的文本材料 MUST 不以主动内容渲染。

#### Scenario: 重名图片附件
- **WHEN** 两个显式选取的附件有同一个原始文件名
- **THEN** 保留两个独立内部身份，要求明确关联，不覆盖或猜测目标用例

#### Scenario: 附件内容后来损坏
- **WHEN** 下载时附件摘要与导入记录不符
- **THEN** 返回材料不可用，不向用户发送声称已核验的损坏字节

### Requirement: 预览确认和可恢复发布

系统 SHALL 在预览后以绑定报告、附件、映射和来源声明的摘要确认导入，执行容量准入并不可覆盖发布。失败、取消、中断和重复请求 SHALL 不造成半可见资产或覆盖已有内容。

#### Scenario: 预览后修改附件映射
- **WHEN** 用户确认时测试与附件的对应关系已变化
- **THEN** 旧预览失效，要求重新预览，不发布不一致资产

#### Scenario: 解析 worker 超时或进程崩溃
- **WHEN** 导入超过资源预算或提交前进程中断
- **THEN** 不出现可用资产，重启标明中断，既有记录不变

### Requirement: 验收关联和引用感知清理

系统 SHALL 将外部结果作为独立来源关联验收对象，不伪造原生运行；被有效修订引用的原报告及附件 MUST 受保护，损坏或未知引用 MUST 阻断清理。

#### Scenario: 试图删除被验收对象使用的外部报告
- **WHEN** 报告仍被某个有效验收修订引用
- **THEN** 删除拒绝并显示引用者，不能仅因外部 reported-pass 就丢弃证据

#### Scenario: 增加独立本机复验
- **WHEN** 同场景同制品外部报告另有关联的本机完整验证
- **THEN** 两种来源都保留，由本机复验满足对应覆盖，外部报告本身仍不标成重新验证过

### Requirement: 逐资产显式授权给当前项目

外部资产默认 SHALL 仅供本机 Viewer/CLI 查询。DSH/MCP 读取 SHALL 要求逐资产、绑定资产摘要与当前登记项目身份／内容版本的显式授权。导入、验收引用、报告内声明及知道 ID MUST NOT 自动授予 Agent 读取权限。撤销或项目变化 SHALL 立即使后续 Agent 查询不可用；原始名称、输出和附件不得进入 Agent 安全投影。

#### Scenario: 未授权或另一项目查询
- **WHEN** Agent 查询未授权、已撤销或仅授权给其他项目版本的资产
- **THEN** 返回统一不可用结果，不泄露存在性和原报告内容

#### Scenario: 已授权资产被引用
- **WHEN** Agent 查询含外部材料的验收对象
- **THEN** 仍逐资产验证当前项目授权，不能借验收对象绕过撤销

### Requirement: 导入交互和宿主出口

系统 SHALL 提供本机预览、确认、取消、查询和附件下载，以及 CLI 和 DSH/MCP 有界只读摘要。导入期间无关操作 SHALL 可用，失败保留旧列表和详情，原始输出 MUST 不默认发送到 Agent 或 PR。

#### Scenario: 导入期间查看另一条运行
- **WHEN** 导入正在解析且用户打开原有运行详情
- **THEN** 详情正常显示，导入进度保持局部且迟到响应不替换当前详情

#### Scenario: 兼容性说明
- **WHEN** 用户查询支持的来源和格式
- **THEN** 返回实际测试的生产者／版本／格式范围及样本来源，不把报告支持表述为支持该框架设备执行
