## Why

现有 Inspector 与 YAML 执行器之间仍有手动转换和维护成本；iOS 可见文字不进入 XML 的案例说明结构验证不能覆盖所有显示内容。第二阶段让用户生成可审查、可维护的测试，并仅对显式声明的新用例引入视觉验证。

2026-09-25 修订以 `dev@REDACTED_REVISION` 为工程基线：草稿、保守定位器修复和像素比较已有首轮实现；本轮方案补齐基线审批、持久引用及跨出口结果一致性。工程实现与真实构建变化/采用验收分别跟踪，既有勾选不代表本次增强已完成。

## What Changes

- B1：从 Inspector 选择生成独立草稿，提供定位器候选、匹配数量、类型转换和预执行检查；选中或生成绝不操作设备。
- B2：增加用例检查与受控修复差异，保留原计划/运行，禁止自动删除断言、跳过业务步骤来变绿。
- B3a：明确区域、遮罩、基线审批、尺寸/方向约束的确定性视觉断言；历史比较仍只读，不自动成为测试门禁。
- B3b：默认关闭的 OCR/语义视觉实验及遮挡评测；不确定不算通过，外发需单独授权；正式 backend 选择需评测决策。
- B4：自研 App 可测试性指南、真实版本升级用例维护成本评估。
- 依赖阶段一 C0 契约；B1/B2 可先交付，视觉实验不阻塞创作功能。
- R1：基线候选预览、显式批准、不可变 revision、规则摘要与来源引用；审批期间材料变化必须重新审查，支持已登记参考图与干净成功运行两种来源。
- R2：Viewer、JSON、JUnit、CLI、MCP/DSH 共用持久化结果投影和故障矩阵，视觉不通过、未执行、取消、恢复与派生导入在各出口保持一致。
- 与第三阶段 R0 引用/读 lease 契约共同集成；先锁定接口再实现，基线批准发布与来源保护原子生效。模块职责收敛和文档核对由第三阶段 R6 统一负责。

## Capabilities

### New Capabilities

- `workbench-assisted-authoring`: 只读检查到草稿、定位器候选及校验。
- `workbench-reviewed-repair`: 用例检查、变更审查与新运行验证。
- `workbench-visual-verification`: 显式视觉断言、基线和模型实验边界。

### Modified Capabilities

- `local-test-workbench`: 扩展原生执行的受支持包装步骤及结果范围，视觉声明不替代结构化 UI 断言或业务 verifier；旧用例行为不变。

## Impact

涉及 Viewer 新草稿区域、共享 selector 转换、workbench-flow/plan/service/store、报告与证据读取。现有 Inspector 仍只读，不修改其临时快照 TTL/Agent 授权；仅用户主动将已脱敏候选复制到独立草稿。Android/iOS 使用同一领域契约，真机分别验收；平台不可比较时拒绝自动视觉结论。视觉由租约内现有截图派生，不开第二连接；MCP/DSH 复用结果投影，不连续传视频。

不做全自动 App 探索、默认模型兜底、无人确认修复、批量改断言、支付/敏感输入自动化。现有有限 AI 导航恢复保持独立，其未完评测仍留在 add-bounded-ai-recovery。

本次细化不新增模型、宿主平台、共享 daemon 或设备调度。Mock、固定图像、伪 Appium、独立进程和打包宿主可完成 R1/R2 工程门禁；两款自研 App、双端真实构建变更及收益数据仍是后续采用依赖。本轮只修订方案，不据此启用功能或关闭 change。
