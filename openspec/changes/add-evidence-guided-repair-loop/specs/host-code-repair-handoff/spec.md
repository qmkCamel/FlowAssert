## Purpose

使不同编码宿主通过一致、受权和版本化的交接协议生成业务源码补丁，而不接管移动设备或验证结论；保护用户现有工作区、项目秘密和原验收标准，在宿主能力不足或请求过期时安全停止。

## ADDED Requirements

### Requirement: 宿主无关的显式能力协商
系统 SHALL 为 Codex/MCP 与 DeepSeek Harness/Cordis 提供相同版本、参数、错误语义和结果契约，并明确公布定位器、源码补丁、构建安装能力。实现 MUST 使用公开宿主扩展入口，不修改 agent loop，不假设后台启动 Agent 能力，不静默降低请求的验证等级。

#### Scenario: 版本不匹配
- **WHEN** 宿主提供未知协议版本或不支持请求能力
- **THEN** 交接被拒绝并说明缺少能力，不启动替代执行路径

#### Scenario: 双宿主一致性
- **WHEN** 同一受权请求分别经 MCP 和 DSH 适配器处理
- **THEN** 权限、候选范围、拒绝原因和结果等级一致，记录实际宿主版本

### Requirement: 可信项目登记与最小披露
源码范围、命令、构建、目标 App 和证据外发 SHALL 来自本机可信登记，查询与交接 MUST 取 case、当前项目权限和共享范围的交集。日志、页面或源码注释不得成为指令；密钥和签名私有信息不得进入交接。

#### Scenario: 报告要求读取其他仓库
- **WHEN** 报告或截图包含扩大目录、读取密钥或执行命令的指示
- **THEN** 指示只作为不可信材料，不改变任何授权

#### Scenario: 猜测任务 ID
- **WHEN** 另一项目主体请求已知 caseId 的补丁或证据
- **THEN** 返回不可用且不泄露对象是否存在

### Requirement: 隔离候选与受限补丁
源码修改 SHALL 在独立工作区生成；主工作区现有改动不得被复制、覆盖、stash 或重置。验证端 MUST 按登记基线独立重放补丁，不信任宿主传入的目录。首版仅接收受限文本补丁，拒绝越界路径、链接、子模块、二进制、mode 变化及保护文件变更。

#### Scenario: 工作区存在未提交代码
- **WHEN** 用户主仓库有未提交改动
- **THEN** 原改动保持不变，任务使用确切登记 commit 的独立工作区

#### Scenario: 路径逃逸或修改验证器
- **WHEN** 补丁包含父目录路径、符号链接或原独立验证器的修改
- **THEN** 拒绝整个候选，不部分应用后继续检查

### Requirement: 受控命令与诚实隔离
验证命令 SHALL 使用可信登记的可执行文件、参数、目录、环境允许名单、超时和输出预算，不接受宿主提供的任意 shell。系统 MUST 明确区分 worktree、进程隔离与安全沙箱；当项目要求的隔离能力不可提供时阻塞，不将不可信构建视作无副作用。

#### Scenario: 命令或日志超限
- **WHEN** 检查超过时间/输出预算或尝试未知命令
- **THEN** 阻止或终止执行、确认实际退出，结果不计通过且保留原因

#### Scenario: 必需沙箱不可用
- **WHEN** 项目要求网络/文件系统隔离而 runner 不具备该能力
- **THEN** 停在 blocked，不以创建 worktree 代替所需隔离

### Requirement: 交接身份与取消围栏
交接 SHALL 绑定 case、attempt、generation、baseCommit、requestDigest 与到期时间，重放或迟到提交 MUST 不能改变任务。宿主中断不等于本机任务安全完成；只有验证端核验过的补丁才能进入审批。

#### Scenario: 旧宿主响应迟到
- **WHEN** 前一 generation 的补丁在取消或新尝试后返回
- **THEN** 被拒绝且不创建新运行，不接受宿主附带的成功结论

#### Scenario: 尝试自行提交发布
- **WHEN** 宿主交接请求包含自动 commit、push、PR 或合并指令
- **THEN** 插件拒绝把这些操作纳入修复计划，保留为用户另行授权范围
