## Purpose

把修复后的验证标准与补丁生成分离，在候选产生前冻结原断言、独立业务检查和回归范围，使用实际执行证据区分软件与设备验证，防止修改预期、跳过检查或伪造报告被误计为产品缺陷已修复。

## ADDED Requirements

### Requirement: 修复前冻结验收条件
系统 SHALL 在补丁前冻结原计划、断言、业务 verifier、视觉/OCR 批准、参数、初始化/清理、依赖、环境、构建与必测范围。无法解析的动态依赖 MUST 阻止自动验证；改变验收标准必须创建新计划并重新审批。

#### Scenario: 间接修改业务期望
- **WHEN** YAML 未变但被引用的 verifier、预期数据或 OCR 阈值被补丁改变
- **THEN** 系统检测摘要变化并拒绝将结果用作原缺陷修复证明

### Requirement: 独立执行与实际证据
正式验证结果 SHALL 由受控验证端实际运行冻结计划生成，绑定确切源码树、补丁、命令、制品与运行身份。宿主自述、上传日志和导入报告 MUST 只作为候选材料，不能直接获得验证等级。

#### Scenario: 宿主提交全部通过报告
- **WHEN** 宿主声称测试全部通过但验证端未运行
- **THEN** 系统仍显示未验证，不允许审批报告直接转换成 verified

#### Scenario: 检查期间源码变化
- **WHEN** 检查前后源码树或验证输入摘要发生未批准变化
- **THEN** 结果失效，必须重新核验，不继续安装与设备复验

### Requirement: 原失败对照与干净复验
系统 SHALL 要求冻结条件下的原失败对照、候选干净复验及关联回归。业务源码路径要求候选原测试在独立重置数据中连续两次通过。未复现原问题、测试环境变化无法解释或残留写入不明确时 MUST 报不确定，不能宣称因果修复。

#### Scenario: 旧版本已经通过
- **WHEN** 对照运行无法复现原失败而候选也通过
- **THEN** 记录两次事实，结论为缺少可复现对照，不计入已验证修复

#### Scenario: 第一次通过第二次失败
- **WHEN** 候选第一次干净复验通过而第二次失败
- **THEN** 该尝试不满足验证标准，保留全部结果，不挑选成功运行发布

### Requirement: 不以削弱测试换取通过
修复 SHALL 不允许跳过必测项、删改原断言、自动批准新视觉基线、放宽 OCR/性能阈值或以 Mock 替换真实 required check。运行时 recovered、cleanup 失败和证据不可用 MUST 阻止干净设备验证结论。

#### Scenario: 导航恢复但业务错误
- **WHEN** 候选可完成页面导航而独立业务校验失败
- **THEN** 结果仍是未修复，不以视觉或模型解释替代业务断言

#### Scenario: 回归被跳过
- **WHEN** 原失败用例通过但冻结回归中的任何必测项 skipped
- **THEN** 任务不得获得所需验证等级，明确列出缺失项

### Requirement: 分层结果与跨出口一致性
系统 SHALL 区分 candidate-only、software-verified、device-verified 及失败/阻塞/不确定/取消/预算耗尽，并在 Viewer、CLI、MCP、DSH 和导出中一致呈现。默认 CLI 要求 device 等级，低等级 MUST 非零；调用方显式要求 software 时只对该范围判定。

#### Scenario: 没有手机的软件成功
- **WHEN** 软件检查全部通过但没有已核验设备运行
- **THEN** 只能输出 software-verified，默认设备验收 CLI 仍非零，显示设备缺口

#### Scenario: 原运行历史
- **WHEN** 修复任务已 device-verified
- **THEN** 原 run verdict 与既有 CI/JUnit 记录保持原失败，摘要展示失败与后续验证链

#### Scenario: 用 Mock 替代真机
- **WHEN** 模拟 provider 或模拟器中的相同测试通过，但没有冻结目标真机的核验
- **THEN** 系统保留模拟执行来源，只支撑软件级结论，不满足 device-verified 或默认真机等级

### Requirement: 验收修订与独立评估
系统 SHALL 只在用户显式请求时将真实复验和历史失败生成新的验收修订候选，沿用权限与完整性检查。修复效果评估 MUST 分开合成安全语料、真实双端样本和非作者研究，不能用 Mock 通过率宣称通用修复准确率。

#### Scenario: 自动发布验收尝试
- **WHEN** 修复完成但用户未确认发布验收修订
- **THEN** 原验收记录保持不变，仅提供可审查的建议输入

#### Scenario: 只有合成评估
- **WHEN** 离线 Fixture 全部通过而未执行真实双端/独立研究
- **THEN** 文档和报告仅声明软件契约通过，真实效果验收继续 pending
