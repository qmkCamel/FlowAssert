## Context

基线只有单设备 `LocalDeviceRuntime`、串行 `WorkbenchSuites` 和确定性像素断言。`workbench-visual-eval.ts` 是只读评测，不是生产 OCR；其 candidate-go 也不自动启用生产。第三项新语义定位能缓解等待问题，却不能补出 XML 本来没有的文字。本项顺序为本机 OCR → 双设备调度 → 第四项验收对象归并，不把二者互相当成验收替代品。

2026-10-01 核对的官方依据：[Apple Vision 文字识别请求](https://developer.apple.com/documentation/vision/vnrecognizetextrequest)具备语言与请求修订参数；[Appium 并行说明](https://appium.github.io/appium.io/docs/en/advanced-concepts/parallel-tests/)及 [UiAutomator2 媒体端口说明](https://github.com/appium/appium-uiautomator2-driver/blob/master/docs/mjpeg.md)指出并行会话需要隔离端口。实现时仍须依据项目实际锁定 driver 版本验证能力，历史文档不是运行成功证明。

## Goals / Non-Goals

目标：让固定区域的明确文字条件成为可审查、可冻结、可评测的附加断言；让两台已登记设备同时执行不同矩阵单元，归并时不丢失失败、取消、清理和证据缺口。

非目标：通用视觉代理、图片指令执行、自动点击 OCR 文本、负向文字断言、未知遮挡保证、云设备、多租户、无条件断线重试。不会通过降低已有视觉 no-go 要求获得“默认可用”。

## Decisions

### 1. 本机识别程序与无设备权限边界

新增 `workbench-ocr.ts` 契约、独立 Swift 帮助程序和进程封装。首个生产候选用 Apple Vision，在 macOS 上本地读取 PNG；不下载语言模型，不调用外部 API，不读取用户屏幕或任意路径。帮助程序只接收 stdin 中有界图片及固定识别参数；stdout 仅版本化 JSON，stderr 脱敏且限长。图片中的自然语言始终是数据，不解析成工具调用。

启动前预检 helper 可执行文件身份／摘要、宿主架构、系统版本、可用请求 revision 和语言集合；显式准备命令使用 Xcode 命令行工具编译已随包发布的源码，产物放私有内容寻址缓存。禁止在 pnpm 安装脚本或首次识别时静默编译。无编译器／语言时功能 unavailable，普通结构测试仍可使用。原生二进制后续可独立签名分发，但不作为首期前提。

选择本机 Vision 而不是默认云模型：保持截图不离开 Mac，并减少服务／密钥依赖；代价是宿主限定与 OS 更新可能改变行为。选择独立进程而非不可终止的进程内回调，确保超时／取消能杀掉自己的子进程并回收资源。适配器是受信本机代码，不宣称沙箱。

### 2. 区域配置、输出和断言语义

配置以项目登记 ID 与 revision 引用，冻结 appId、platform、允许构建、图片几何、方向、语言、识别版本、整数像素 ROI、规范化规则、最低置信门槛、expected 文本、可选明确 blocker 文字和评测记录摘要。不能由 YAML 指定 helper 路径或网络端点。

首期只支持单行／单观察框的完整精确匹配，可配置 NFC 和首尾空白处理；不做大小写折叠、模糊、正则或自动跨行拼接。只保留第一候选及受限候选信息，要求唯一目标。配置文本长度最多 256 字符；区域 1 个、blocker 最多 10 项。识别输出包含文字、置信分、框坐标、helper／系统版本、原图及裁剪摘要、耗时、配置摘要。置信分不是准确率概率，不能单靠高分替代冻结评测。

新编译节点 `assertTextInRegion: { profile: 登记标识 }` 在既有运行租约内获取该步检查点 PNG，保留完整原图及裁剪派生关系；不新增媒体订阅，不使用过期 Viewer 帧。UI 结构断言、OCR 视觉维度和业务维度独立，OCR 不证明持久化。

| 条件 | 断言结果 | 说明 |
| --- | --- | --- |
| 已放行配置、身份／几何匹配、唯一期望文字满足门槛 | pass | 只证明冻结截图的指定区域识别条件 |
| 已放行配置、区域唯一可读完整文字明确不同 | fail | 保留期望和实际供复核，不自动改期望 |
| 明确 blocker 被高置信识别 | fail | 提供已识别遮挡证据；未识别不证明无未知遮挡 |
| 缺字、低置信、多个目标、截断、几何／版本不匹配 | inconclusive | 不能当作 assertNotVisible 成功 |
| 取消、超时、帮助程序坏输出、配置未放行 | inconclusive／运行取消 | 不自动跳过强制断言、不降级为结构通过 |

仅调试预览可以运行尚未放行的配置，明确标“候选”，不进入生产 verdict。预览只读存档图片或用户显式获取的新快照，不触发设备动作。输入图片限 16 MiB、4096×4096，裁剪后送识别限 4 MiB，输出最多 256 框／256 KiB，单次预算 10 秒；进程数最多 2，排队最多 4。预算包含解码与识别；子进程退出后才释放槽位。

### 3. 从评测到有限启用

沿用现有开发／冻结集隔离以及真实授权图片要求；新增字段记录 ROI、期望、语言、设备几何、文字可读性和明确遮挡标签。新 OCR 评测在采集时就冻结两个集合：放行范围集最低 20 个真实授权、人工可明确判定的正反例，两个 App／页面组，正反例各不少于 5 个，含相似字、明暗主题及明确遮挡；安全拒绝集另覆盖不可读、截断、歧义、旋转、范围不匹配和图片提示注入。拒绝集不能产生通过，预期不确定是正确拒绝而非放行集成功。两个集合分别列出数量、结论和拒绝率，禁止跑完后把失败样本从放行集挪到拒绝集。开发与冻结图片及近重复页面分组隔离，不只检查相同文件 hash。

初始放行门槛：放行范围集零错误通过、零错误失败、零无法确认，安全拒绝集全部符合预标注的拒绝语义，另报告端到端 P50/P95 和取消回收；统计置信区间与样本量限制，不外推为普遍准确率。真实数据达不到则保留 no-go，不能为了做完任务放宽指标。新区域 OCR 有独立评测契约，既有通用语义候选评测和 no-go 规则保持不变。candidate-go 之后仍需人工批准限定 profile，记录审批者、范围、评测摘要与 helper／OS 版本；默认生产仍关闭，只有匹配批准 profile 的显式新断言启用。版本或范围变化重新评测，不能全局解锁 OCR。

### 4. 矩阵以独立单设备运行时组成

新增 `LocalDeviceMatrix` 协调器和本机登记文件。每槽位具 slotId、platform、明确 UDID、配置 ID、端口集合与资源标签。首期 2 个槽位，最大并行度 2；每槽同时最多一个 case，每矩阵最多 100 个单元，只允许一个活动矩阵。使用确定性 FIFO 分配固定平台／设备单元，不隐式选择其他设备。

每槽位由独立子进程拥有 `MirrorService`、`WorkbenchApplication`、工作目录和 Appium 会话。父进程只负责矩阵状态与受控 IPC，不调用 ADB/WDA 绕过 provider；单设备手动模式保持原样，同一 UDID 跨模式使用既有机器级 claim。父子控制用创建时绑定的私有通道，身份包含矩阵 ID、槽位 ID、attempt ID、owner generation 与单调序号，拒绝迟到／冒名消息。

不同槽位拥有独立 Appium 管理实例／显式外部端点，检查 Android systemPort、iOS wdaLocalPort、媒体 mjpegServerPort、必要的 WebView 端口及 Xcode 派生目录不冲突；不依赖 `sessionOverride`。端口先在登记配置中分配并预检，绑定竞争即失败，不杀外部进程“修复”端口。媒体仅为用户选中槽位开启有界预览，其余设备不自动追加持续视频。

开始矩阵时冻结计划、项目快照、制品、fixture 和覆盖范围；所有槽位预检通过且容量预留后才派发第一个动作。副作用 fixture 默认不可并发；只有显式 `parallelSafe`、独立资源命名空间和明确清理契约的 case 才能同时执行。存在相同独占 resourceKey 时串行排队；无法证明隔离则拒绝并行，而不是让测试相互污染。

### 5. 调度、取消、中断与重新执行

协调器持久化 accepted → preparing → running → cancelling／finalizing → finished；每单元 queued → claimed → running → terminal。派发前写意图，收回子结果后校验单元／来源身份、清单与文件 hash，才标完成。父进程持有协调目录唯一 owner；子运行写在各自 store，禁止多个进程共享同一可写 Store。

全局取消停止排队派发，并逐槽请求既有取消链；单槽取消不终止其他槽位。等待在途 mutation 收敛，确认自己的进程树退出与清理后再释放 claim；无法确定动作结果则隔离槽位，保留写入封锁与人工重连要求，不能重用它跑后续 case。

设备断线时当前单元 inconclusive，相关槽位后续单元标 blocked，另一槽继续。父进程／子进程崩溃后的重启不自动重放；使用进程启动身份、nonce、generation 防止误回收 PID 复用或其他 owner。保留 journal 和未解决 claim，确认会话终止后才允许显式新 attempt。复跑要求已登记安全重置／独立数据及用户确认；原失败和中断保持可见，禁止把复跑直接改写旧单元。

### 6. 材料、引用与统一归并

`MatrixResult` 保存矩阵输入摘要、槽位声明、预检、每单元全部 attempt、冻结投影和缺口。每条结果引用通过协调器登记的 storeId 解析；用户不能用路径访问任意 store。子 store 在存活 owner 下为矩阵发布 `matrix:attempt` 引用，协调器保留引用回执；只有所有必要材料确认后发布最终清单。父进程崩溃遗留引用采用多保护原则，不自动撤销。

第四项 SourceResolver 新增 matrix-cell 类型，委托协调器获取存活子 store 的只读租约；离线 store 通过显式只读打开流程获取互斥读取，不破坏活动 owner。服务 unavailable 或引用损坏降为不完整，不能拿缓存投影显示当前 clean。安全导出是固定协议复制，不提供任意目录读写代理。

归并逐单元保留 UI、业务、视觉、清理、证据；全部要求单元 clean 才返回 0。确定失败优先 1，剩余不完整／blocked 优先 2，仅纯取消为 130；所有原因同时保留。跳过、空选择、断线与迟到结果均不能被成功槽位抵消。第四项验收对象仍校验本次提交／制品，矩阵只提供材料，不决定需求覆盖。

### 7. 用户入口和宿主边界

Viewer 新增区域框选／识别预览／配置来源区，以及设备矩阵配置、每槽进度、选中槽媒体、取消、复跑和归并表；用户确认的配置才保存，候选不能自动批准。

CLI 提供 `ocr doctor/prepare/evaluate` 与 `matrix validate/start/status/cancel/retry`；准备命令不得后台自动执行。服务 API 使用 `/api/workbench/ocr/*` 与 `/api/workbench/matrices/*`，所有写请求同源并按现有控制政策校验。新增 `mobile_matrix_status` 只读工具；矩阵启动／取消首先限 Viewer／CLI 的显式授权路径，不把旧单设备 Agent 工具悄悄改成多设备操作。DSH 与 MCP 复用应用服务和版本化摘要，流媒体不进入工具结果。

长操作本地反馈；OCR 正在识别时可切历史，某槽运行时可查看另一槽；启动按钮防重复，错误保留上一份完整矩阵和识别结果。切换槽位／截图后旧响应不得写入新对象；取消显示实际子进程回收状态，完成时间取领域事件。

### 8. 分层验收

| 层级 | 必须验证 | 不得替代 |
| --- | --- | --- |
| 确定性软件 | 假 OCR、边界图像、双 Mock、伪 Appium、端口冲突、容量拒绝、IPC 注入／迟到 | 真实识别质量、双设备稳定性 |
| 本机运行时 | 实际 Vision helper、真实 PNG、超时回收、宽窄屏交互截图、同包 CLI/MCP/DSH | 授权冻结集／真机业务 |
| 真实验收 | 授权真实图像门禁；Android＋iPhone 各 20 次矩阵运行，断线／取消／重连，独立业务与清理核对 | 商用大规模设备农场能力 |

双端总计 20 轮矩阵，每轮两槽各一业务 case；额外每平台各 3 次断线、单槽取消、全局取消与显式复跑。要求零跨设备动作、零未处理资源残留、零错误通过，失败／中断材料完整；运行耗时与串行对照同样记录，不预设“快两倍”。任何未完成真实验收保留任务未勾选。

## Risks / Trade-offs

- OCR 看到了错误页面上的相同文字 → 配置绑定 App／页面前置结构条件／ROI／构建，保存全图，不能只保留裁剪。
- 高置信错字或模型版本漂移 → 冻结反例评测、限定批准 profile、版本变化重新验证。
- 两设备共享业务账户污染 → 显式并发安全 fixture 与资源键，不兼容就串行或拒绝。
- 进程退出与设备调用完成不同步 → 写入封锁、owner 确认与可恢复 journal，不凭超时直接释放设备。
- 多进程储存／引用复杂 → 每 store 一个 writer，矩阵引用回执、只读解析和故障切点测试；不共享可写根目录。

## Migration Plan

第四、五项工程门禁完成后，先提交 OCR 契约及预检，再实现 helper 与评测、显式断言、界面；随后更新运行时边界 ADR，完成双槽配置／调度／故障恢复／归并／界面。最终串行跑项目四项门禁及打包宿主探针。未满足识别门槛只开放调试预览，未满足双真机门禁只报告工程验证，不能归档整个 change。回滚默认关闭新入口，保留所有矩阵记录、引用与 claim 供恢复，不删除旧单设备数据。
