## 三项共同约束

- 所有新实现先在独立工作树推进，保留原工作区和上一分支的未提交材料；每项工程验证后仅提交明确路径，不自动推送／合并。
- 每项使用 `openspec status`、`openspec instructions apply` 获取当前状态与上下文，按任务即时勾选，需求／设计发生实质变化时先更新方案。
- 单元与集成测试、浏览器运行期交互、截图检查、构建和打包分别留证；构建与浏览器套件串行运行。
- DSH 已验证基线为 0.1.5-rc.2，MCP 与 DSH 共用核心应用服务，不修改任何宿主 agent loop。
- 长操作遵循 `user-action-contract`：局部进度、可取消、重复提交保护、无关交互保持可用、失败保留已有结果。
- 英文标题 `Why`、`ADDED Requirements`、`Requirement`、`Scenario` 以及 `SHALL`、`WHEN`、`THEN` 是 OpenSpec 模板／解析格式；需求描述、设计理由、任务和验收内容使用中文。代码字段和产品名称保持原拼写。

## 明确不混淆的能力

- PR 摘要是本机可审查产物，不是自动 GitHub 评论或远程质量门禁服务。
- 外部结果适配器不是外部执行器适配器；本次不启动 Maestro 或另一个 Appium runner 控制设备。
- OCR 仅验证批准范围内明确文字，不证明所有遮挡不存在，不让图片控制设备。
- 双设备是本机明确资源的并行，不代表设备云、多租户或任意设备数量。
