## Why

工作台已能生成单次运行证据，但评审者仍需手工回答“这次提交的哪些场景、哪些构建、哪些设备真正验收过”。需要把代码变更、验收范围和不可变运行材料关联成一份可审查的对象，而不是把一次绿色结果当成整个变更通过。

本变更对应产品路线图第四项，接续 `REDACTED_REVISION` 的首次验收、语义等待和关联复验。状态：工程实现及门禁通过（21/24），真实业务及非作者验收未完成。验证见 `docs/change-acceptance-validation.md`。文档正文使用中文；保留 OpenSpec 解析器需要的英文结构标记和代码标识符。

## What Changes

- 新增本机“变更验收”对象：仓库标识、完整提交摘要、可选 PR 编号、构建摘要、要求覆盖的场景及设备环境、各验证维度和剩余缺口。
- 每次生成不可变修订，绑定运行清单和证据摘要；原失败、恢复和后续复跑同时保留，不按最新一次成功覆盖历史。
- 提供统一的严格验收判定、JSON 与可粘贴到 PR 的 Markdown 摘要；默认只导出元数据，不附带图片、日志、参数、路径或凭据，不自动评论或更新 GitHub 状态。
- Viewer 提供创建、预览、刷新生成新修订和下载；CLI 与宿主共享应用服务。已有 DSH/MCP 工具行为不变，新增能力通过独立的只读摘要入口接入。
- 引用保护、容量准入、取消、失败保留旧修订以及重启后的完整性核查纳入交付，不仅实现一段 Markdown 格式化代码。

## Capabilities

### New Capabilities

- `change-acceptance-records`：变更验收对象、范围覆盖、来源与证据绑定、严格聚合、修订及安全摘要出口。

### Modified Capabilities

无。通过新增验收层组合既有运行投影；不重定义旧运行的 `pass`、`recovered` 或导入分享语义，不修改旧运行清单。

## Impact

- 新增领域契约、服务、持久化、Viewer 模块及 CLI 子命令；在 `WorkbenchApplication` 中组装，复用 `WorkbenchReferences`、运行投影和容量准入。
- 以 macOS 本机 Android/iOS 运行记录为首期边界，PR 标识只作关联，不要求 GitHub 登录。已声明提交和二进制摘要必须标明来源，不能伪称设备实测证明了代码与构建的关系。
- 不新增执行引擎、云服务、设备连接或自动发布；不更改 Harness agent loop。验收对象为第五项外部结果和第六项设备矩阵预留带来源的结果引用类型。
- 实施顺序：本变更工程门禁通过后再执行 `add-external-test-assets`；真机及非作者评审验收单列，未完成不归档、不宣称产品采用完成。
