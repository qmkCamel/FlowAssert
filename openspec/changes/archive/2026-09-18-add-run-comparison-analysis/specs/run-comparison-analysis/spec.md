## Purpose

提供基于本机归档的确定性失败分析与跨次比较，让用户能够核对同用例不同运行的画面、结构、断言、业务结果与耗时，并明确证据缺口、可比性及推断边界，保持原始测试判定和证据不变。系统还 SHALL 把领域语义压缩为可回钻的 Diagnostic Context，供 Viewer、MCP 和任意上层 Agent 消费；Agent 推理不属于比较事实或 verdict。

## ADDED Requirements

### Requirement: 新运行比较身份
系统 SHALL 为新运行冻结用例身份、输入与计划指纹、平台及可获取的执行环境，未知字段明确标记；不得用标题代替用例身份或暴露秘密输入。

#### Scenario: 同标题不同用例
- **WHEN** 两条运行标题相同但登记用例身份不同
- **THEN** 系统不自动推荐为同用例基线

#### Scenario: 历史记录缺少新契约
- **WHEN** 用户选择缺少比较元数据的历史运行
- **THEN** 系统说明比较不可用并保留原历史查看，不迁移或猜测字段

### Requirement: 明确基线与可比性
系统 SHALL 推荐同用例、输入、平台及 App 身份的较早成功运行，排除 recovered、flaky 尝试和已知证据不完整记录；人工选择必须展示身份和环境差异。

#### Scenario: 没有合适基线
- **WHEN** 候选只有恢复成功或不同参数的运行
- **THEN** 系统不自动将其当作正常成功基线

#### Scenario: 跨平台查看
- **WHEN** 用户人工选择 Android 与 iOS 运行
- **THEN** 系统仅并排查看并标记 review-only，不进行自动像素或结构判定

### Requirement: 保守步骤对齐
系统 SHALL 使用计划身份、控制上下文与执行迭代对齐步骤，区分新增、删除、未执行和歧义，不得仅用步骤序号对齐变化后的计划。

#### Scenario: 插入步骤和重复动作
- **WHEN** 新计划插入动作且存在多个相同动作无法唯一匹配
- **THEN** 系统保留未匹配与歧义标记，不强行配对

#### Scenario: 取消与恢复
- **WHEN** 运行中途取消或某一步触发 AI 恢复
- **THEN** 系统分别展示未执行后续步骤或原步骤的恢复子过程，保留原失败

### Requirement: 分维度证据比较
系统 SHALL 分别比较截图、结构、UI 断言、业务结果、清理、AI 恢复和耗时，并标记每维可比性、完整性及证据引用。像素差异不得自动成为测试失败。

#### Scenario: 图像尺寸不同
- **WHEN** 两侧截图尺寸或方向不同
- **THEN** 系统提供并排预览并标记像素分析不可比，不隐式缩放计算差异

#### Scenario: 使用遮罩
- **WHEN** 用户指定截图忽略区域
- **THEN** 系统显示并保存遮罩配置，原图仍可查看且原断言不变

#### Scenario: 耗时信息不完整
- **WHEN** 某阶段缺少耗时或基线耗时为零
- **THEN** 系统不把缺失当零且不产生无意义比例，不将两次测量称为统计回归

### Requirement: 有依据的失败分类
系统 SHALL 基于结构化事件输出多标签失败事实及证据，将推测与事实分开，并允许 unknown；不得修改原运行判定。

#### Scenario: 模型主动放弃
- **WHEN** 模型返回 abstain 而没有显式服务拒绝事件
- **THEN** 系统标记主动放弃，不归类成服务故障或模型 refusal

#### Scenario: 设备超时和材料缺失并存
- **WHEN** 归档同时包含设备命令超时和截图采集失败
- **THEN** 系统分别列出两项事实，不据此断言硬件损坏或产品缺陷

### Requirement: 首次差异的证据边界
系统 SHALL 仅对顺序和前序证据完整的对齐前缀给出首次可确认分歧；分歧不得被称为已证明的根因。

#### Scenario: 前序证据缺失
- **WHEN** 已找到一个差异但此前步骤有证据缺口
- **THEN** 系统显示最早已观察差异及前序缺口，不声称全程首次差异

### Requirement: 确定性证据降噪与级联识别
系统 SHALL 从已对齐的运行中确定性地归纳最早可确认/已观察分歧、其后的级联差异、环境限制与证据覆盖；不得把截图变化、时间相关性或后续差异本身表述为业务失败、根因或因果证明。

#### Scenario: 首分歧后的未执行步骤
- **WHEN** 一个已确认分歧导致后续导航未发生，且后续步骤位于明确对齐路径上
- **THEN** 系统将后续差异标记为 downstream 并保留各自事实与证据，不将其重写为根因

#### Scenario: 历史聚合
- **WHEN** 系统按相同逻辑用例身份聚合多次比较
- **THEN** 系统仅展示可复核的频率、环境切片、覆盖与证据引用，不从相关性断言因果

### Requirement: Agent-friendly Diagnostic Context
系统 SHALL 从同一比较报告生成版本化、最小化的 Diagnostic Context，至少包含 case/flow/attempt 身份、两侧 verdict 事实、首分歧、级联差异、业务/断言/设备等分类、环境差异、证据覆盖及稳定 evidence refs。该 Context 不得包含秘密输入、宿主绝对路径或默认内嵌的原始截图/XML/log。

#### Scenario: Agent 按需回钻
- **WHEN** Agent 读取 Diagnostic Context 后需要核对某项事实
- **THEN** 系统仅允许它按已登记的 reportRef 或 evidenceRef 请求有界的受权详情，不接受自由文件路径或整包原始材料导出

#### Scenario: Agent 给出解释
- **WHEN** 任意上层 Agent 根据 Diagnostic Context 生成解释
- **THEN** 该解释被视为外部、可选推理，不修改比较事实、基线选择、失败分类或原运行 verdict

### Requirement: 只读完整性与可复现报告
系统 SHALL 校验实际分析字节的哈希，独立保存输入指纹、规则版本、选项、结果依据和派生产物哈希，不修改原归档、不调用手机或模型。

#### Scenario: 文件损坏或分析期间变化
- **WHEN** 引用材料哈希不符或输入清单在分析期间改变
- **THEN** 系统标记损坏或 stale，保留有效维度与限制，不输出完整可信结论且原运行不变

#### Scenario: 重启查看报告
- **WHEN** 用户重启后打开已完成比较
- **THEN** 系统校验报告产物并明确原材料缺失或变化，允许下载不含原始媒体的本机报告

### Requirement: 有界异步交互
系统 SHALL 异步受理分析、显示局部进度、支持有界取消并限制输入与并发；分析过程中无关 Viewer 控制保持交互，失败保留上一份可用结果。

#### Scenario: 慢任务与取消
- **WHEN** 比较超过 300ms 且用户继续操作无关控件后请求取消
- **THEN** 系统持续展示任务进度并响应控件和取消，不清空此前完整报告

#### Scenario: 中断和资源超限
- **WHEN** 任务因宿主重启或输入超出预算而无法完成
- **THEN** 系统分别标记 interrupted 或明确受限维度，不自动重放任务、不静默遗漏

### Requirement: 本机访问边界
系统 SHALL 复用本机授权和来源检查，仅按登记 ID 读取材料，不接受任意文件路径，不向模型或外部服务发送比较材料。

#### Scenario: 越界或恶意材料
- **WHEN** 请求包含越界路径、symlink 越界、未授权来源或包含外部实体的 XML
- **THEN** 系统拒绝相应请求或材料，不读取归档之外内容
