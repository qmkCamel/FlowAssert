## Context

基线 dev@REDACTED_REVISION，保持宿主无关模块化单体。旧消费记录与新引用账本共存，不批量改写用户归档。

## Goals / Non-Goals

Goals：comparison/share 新发布必须先持久保护再可见；退休先 tombstone 再释放引用；执行消息版本、结构、顺序可验证；固定规模测量可复跑；旧记录及单设备 owner 不变。

Non-Goals：不迁移全部 suite/baseline/Agent 生产者，不实现插件市场、多引擎、数据库替换或通用任务框架。不在缺少真机时宣称真机验收。

## Decisions

1. 新消费记录附带版本化 referencePublication 标识及 ref IDs。统一工具创建 v3 引用并在同一 Store mutation gate 内先发布保护，再提交消费记录。comparison 使用 run 级保护（空 evidenceRefs 表示保护整个 run），share 记录所选材料。发布中断保留已落盘引用，宁可保守泄漏，不删除保护来隐藏错误。
2. 显式内部 retire 方法只允许终态比较/已生成分享映射；先持久写入退休标记，再按消费者 kind/id 撤销引用。退出程序不退休。legacy snapshot 对无标识的旧记录保持原有保护；对新记录校验标识、目标与账本一致，缺失/未知引用 fail closed，退休后残留引用仍继续保护。
3. Worker v1 消息带协议版本和单调序号；主线程 schema 校验后再派发工具，限制工具 ID、步骤开始/终止顺序与结果时点，异常停止并等待 Worker 终止，不自动重放设备写入。固定 AppClaw 类型在适配边界内，不引入第二执行器。
4. 查询基准在新建临时目录构造固定 100/1,000/10,000 条完成记录，记录数据形状、耗时与内存，区分 status/get/list/retention/triage 查询。测量不是生产 SLO；必要的并发上限与摘要优化保留原有可信投影，不以跳过复验提速。
5. 录屏失败先保留时序证据并尝试确定性重现，不以重跑成功宣称修复。范围内可修复下载/绘制时序问题，但不改变录像证据语义。

## Risks / Trade-offs

- 新旧读取器混用 → 保留旧扫描回退，未知格式阻止删除；新退休记录被旧版额外保护属于安全回退。
- gate 内发布失败 → 所有发布切点测试，先有保护后可见；错误不能形成无保护的新报告。
- 上游消息格式变化 → 严格失败并保留诊断，固定版本真实 Worker 与打包探针验证。
- 无真机或宿主授权 → 只做可用设备检查和软件验证，单列未验项，不访问外部业务。

## Migration Plan

先同步并归档上轮规范，再实现协议和消费者，补故障/兼容测试、规模测量、软件门禁及可用真机验收。更新 ADR、TODO、验收记录后限定范围 commit/push 到功能分支；合并 dev 另行确认。

设备可用性以本轮发现结果为准。生产规模预算待本轮基准后给出建议，不预先承诺性能数字。
