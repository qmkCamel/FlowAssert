## Context

当前 README 约三百行，先后叠加了产品定位、Mock 快速开始、完整工具清单、架构图、源码工具链、DSH 安装、MCP 注册、Android/iOS capabilities、配置安全项、维护者探针、项目记录和验证命令。内容本身大多正确，但同一事实同时存在于 README 与 `docs/` 专题文档，导致首页认知负担和后续维护漂移。

主要读者分为三类：第一次了解产品的使用者、准备连接 DSH/Codex/真机的使用者，以及维护源码和发布的贡献者。README 应先服务第一类，并把后两类引导到稳定入口。

## Goals / Non-Goals

**Goals:**

- 让读者在 README 前半部分理解“AI Agent 的本地移动设备桥接层”这一定位、目标用户、核心价值和 Viewer 的辅助角色。
- 保留不依赖手机的五分钟 Mock 激活路径，让产品说明可以立即转化为体验。
- 为安装、MCP、真机、架构、安全、开发和验证建立清晰且不重复的导航。
- 让中英文首页拥有相同的信息架构、版本事实、边界和链接。
- 把源码开发与维护者命令收敛到独立的中英文技术指南。

**Non-Goals:**

- 不修改产品能力、运行时接口、配置默认值、Viewer、发布包或依赖。
- 不把所有专题文档合并成一份新的大型手册。
- 不在 README 承诺尚未完成的设备矩阵、稳定版、公共 npm 或远程设备网格。
- 不删除安全、验收和研究记录；只调整首页的信息层级。

## Decisions

### 1. 使用“产品首页 → 技术指南 → 专题文档”三层结构

README 只保留定位、价值、产品结构、场景、核心能力、Mock 快速体验、成熟度、限制和下一步导航。新增 `docs/technical-guide.md` 与 `docs/technical-guide.zh-CN.md`，集中源码工具链、本地开发、构建打包、探针、验证和技术文档地图。DSH/MCP 安装、真机、架构、安全和发布细节继续由现有专题文档负责。

备选方案是只删减 README 并直接散链到全部专题文档。该方案首页会变短，但贡献者缺少统一技术入口，因此不采用。

### 2. 以产品任务组织 README，而不是以组件或实现组织

首页顺序固定为：一句话定位与状态、产品解决的问题、工作方式、适用人群/场景、核心体验、五分钟 Mock、成熟度与边界、按目标选择下一份文档。`LocalDeviceRuntime`、provider、revision、TTL 等术语只在帮助解释安全价值时出现，详细 contract 不留在首页。

备选方案是保留现有“架构/前置条件/配置”顺序并增加产品序言。它仍会让技术内容占据主体，不能解决定位模糊问题。

### 3. README 保留唯一的可执行快速开始

五分钟 Mock 命令和一个对应语言的 Viewer 截图保留在首页，因为它们是最低摩擦的产品体验。DSH tarball、MCP 注册、真机 capabilities、物理探针和发布命令全部迁移到技术指南或既有专题文档，只在“下一步”表格中保留链接。

### 4. 中英文采用同构结构和语义对齐

`README.md` 与 `README.zh-CN.md` 使用相同章节和链接集合；`technical-guide` 也提供中英文版本。翻译不要求逐句直译，但版本号、支持基线、安全边界、状态和外链目标必须一致。每份文档顶部提供语言切换。

### 5. 以既有专题文档作为事实源

- 产品边界：`docs/product-shape.md`
- 架构：`docs/architecture.md` 与 ADR
- 安全：`docs/security.md`
- DSH Beta：`docs/beta-installation.md`
- MCP/Codex：`docs/mcp-hosts.md`
- Android/iOS：平台真机指南
- 验证与路线图：`docs/validation.md`、`docs/milestones.md`

技术指南只解释入口和推荐顺序，不复制完整 capabilities、配置枚举或验收矩阵。

## Risks / Trade-offs

- **风险：README 过度产品化后贡献者找不到命令。** → 在首页显著提供“技术与开发”入口，并让技术指南包含完整本地开发和门禁命令。
- **风险：中英文后续漂移。** → 保持同构标题和链接，使用脚本/检查验证关键版本、主要链接与章节存在。
- **风险：删除细节时丢失唯一信息。** → 对每个被移除段落建立去向映射；若现有专题文档缺失，再补入技术指南，而不是直接删除。
- **风险：产品文案夸大当前能力。** → 明确 developer preview、已验证基线与未完成矩阵，区分现有能力和最终形态。
- **取舍：README 不再是离线全量手册。** → 换取更清晰的首次认知和更低的重复维护成本；仓库内相对链接仍保证完整信息可达。

## Migration Plan

1. 建立中英文技术指南并接收现有开发/验证入口。
2. 按同一产品信息架构重写两份 README。
3. 核对所有移除内容是否由技术指南或专题文档承接。
4. 校验相对链接、关键版本与中英文结构，执行仓库文档/公开发布门禁。
5. 若重构效果不符合预期，可恢复两份 README；新增技术指南本身不影响运行时，可独立保留。
