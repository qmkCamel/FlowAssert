## 前提和材料

招募 5 名非实现作者，按真实目标用户角色记录报告作者/分析者/接收者。允许本机现场或各自离线阅读，不上传私有归档。仅使用有使用授权且已复核的图片；分别登记 Android/iPhone 型号、设备 OS、采集日期、原文件摘要、源 schema、真实信号来源和候选包摘要。

准备 50 条混合运行：通过/失败/取消/中断/恢复/未确定，包含同名不同 caseId、无身份旧记录、未知构建、缺图/坏 hash、导入与派生。诊断报告至少 20 步、3 个失败；导出报告 3 步，其中一个真实分辨率图片含指定的合成敏感区域。至少有一份来源通过但派生未重验、一份必需 runtime 未执行及一份健康来源不支持。录像和子运行须来自真实登记材料，不能伪造关系。

当前软件 fixture 是 1170×2532 合成图，归档 iOS 是 1290×2796；它们不等同于完整双平台真实材料。脱敏离线报告会省略原始条件与观察文本，研究必须检查这种省略是否妨碍接收者定位；不要提前讲解答案。

## 执行顺序和计时

1. 给出目标运行的设备、日期和状态，要求找到报告，说出状态、设备、构建。页面可用时开始计时，目标 ≤60 秒。
2. 打开至少 20 步报告后，要求定位首失败，说出预期、实际和对应证据。目标 ≤30 秒；只回答“失败”不计成功。缺证据必须主动说明。
3. 要求解释来源通过、派生未重验、业务未验、健康不支持和文件 hash 各代表什么。不把未知当通过、不把自包含 hash 当来源真实性证明。
4. 给出含一个合成敏感区的三步报告，要求遮蔽、检查最终预览、确认并下载 HTML。目标 ≤180 秒；检查导出像素和源文件 hash，漏遮不计成功。
5. 另一接收者在断网时打开文件，指出失败步骤和省略范围。目标 ≤60 秒，不能依赖作者口头补充。

主持人只在用户明确请求时帮助；记下原话和时间，受提示完成与独立成功分开。每项记录秒数、错误/漏遮、帮助次数、键盘可用性和语义误解。至少 4/5 独立成功才达到 D10；每项分别统计，禁止合并平均值掩盖失败。
